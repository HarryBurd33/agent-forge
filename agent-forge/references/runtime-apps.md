# Implement a runtime-backed agent application

Use this route when the requested agent needs an actual service, such as durable sessions, typed runtime tools, event ingress, specialist children, schedules, or a streaming client. Preserve an established framework and follow its installed documentation. A direct calculation or known fixed procedure can use the existing prompt, script, or tool. For a new application with runtime needs and no framework preference, evaluate [Eve](https://github.com/vercel/eve) as the default candidate against the deployment, language, persistence, and authority requirements. Record which runtime capabilities the request depends on.

## Set up the selected version

1. Inspect the workspace, package manager and lockfile, Node version, existing runtime and app conventions. Reuse the working setup. Check framework engine requirements before installing. For Eve, inspect the exact published release and its CLI, then use that release's supported scaffold only within the authorized project. A selected release and the scaffold's resolved dependency can differ. Pin the package exactly and verify the effective version in the manifest, lockfile, and installed package before writing API-dependent code.
2. Locate the resolved package, including package-manager links, and read `node_modules/eve/docs/README.md` or the equivalent path for that installation. Follow its task links and inspect relevant public types when necessary. Prefer documentation shipped with the selected package over moving examples. When package docs are unavailable, use release-matched upstream material or the [official Eve documentation](https://eve.dev/docs), verify the APIs against the selected release, and record any remaining uncertainty.
3. Map the requested outcome to the smallest set of app files, tool contracts, and host resources. Record versions, lockfile, doc paths, and how to invoke the app. Obtain only the scopes the selected use case needs. Provider connections, webhook registration, deployment, live messaging, and paid inference require authority for those effects. Local synthetic validation can proceed with scoped inputs and mocked model responses.

For a fresh npm-based Eve app, the command shape below uses the release qualified by the local fixture. Choose the actual release for the target before running it. Use the matching package-manager commands in an established workspace.

```sh
eve_version=1.0.0-rc.9
npx --yes "eve@$eve_version" init my-agent --non-interactive
cd my-agent
npm install --save-exact "eve@$eve_version"
node -p 'require("./node_modules/eve/package.json").version'
```

For a new Eve app that needs real inference, use a Vercel AI Gateway model identifier by default and confirm availability, access, and spending authority before the first live call. Follow an explicitly selected provider when the project needs one. For synthetic checks use a local model fixture with no provider keys. Vercel Agent is a separate product for Vercel's code review and production investigation workflows.

Keep the working procedure in the project playbook. Index the authored app files, invocation, tool schemas, fixtures and evidence in the toolbox or link the authoritative repository resources. Reuse working implementations, preserve user customizations, and freeze the outcome checks before the first representative run. See [project contracts](contracts.md) and [engineering guidance](engineering.md).

## Verify the actual app

Build and typecheck using the project's real commands. Run a bounded representative fixture through its normal route with a fresh input and an independent expected result. Capture model identity, tool results and terminal state. Confirm invalid input is rejected before any protected effect, preserve unknown accepted results for later observation, and reconcile interrupted effects before retrying. Stop test processes or schedules you own and record their terminal status.

Label each capability by the evidence obtained, such as documented, configured, compiled, locally executed, or provider verified. State the exact follow-up check for any missing outcome. Synthetic mock runs establish framework mechanics and fixture behavior. Cross-process state, crash recovery during an effect, schedule cadence, provider authentication, and model quality each require their own observations.

## Preserve browser identity, stream position, and cancellation

An authenticated channel is only one boundary. Check who may read, send to, resume, and cancel each session. In the pinned local example, a single loopback gateway owns that policy and keeps its backend operator credential out of the browser. Eve's trace audience and bearer configuration alone do not establish the example's per-session ownership. Preserve the ownership record across ordinary restarts and reconcile an uncertain create before retrying. Qualify production authentication, concurrent gateways, storage loss and crash recovery separately.

Inspect and forward the SDK's required stream headers and cursor query fields through an adapter. The rc.9 client requires its stream-version header. A delivery result read can advance the handle's cursor; use separate display and writer handles when a detached display must later catch up. Test a send while detached, then reconnect from the saved nonzero cursor and verify both the displayed result and the absence of duplicated server work. Reloading a document may reconstruct history from zero; state precisely which cursor behavior was observed.

A cancelled reader leaves server work running. Cancel the observed server turn through the supported control API, then require its terminal cancellation event and the tool's interrupted result. A submitted control is not a completed cancellation. Use a no-effect delayed tool for this test before relying on cancellation around external effects.

A development server can add optional dependencies even when the initial package install was pinned. Inspect the selected sandbox/provider's install behavior. For the rc.9 local fixture, explicitly selecting the pinned just-bash provider with automatic installation disabled prevents a session-preparation step from rewriting the dependency graph. Check manifest and lock hashes after representative execution as well as before it; a successful initial build is insufficient. A missing required provider must produce a visible failure when that provider initializes; merely loading a skill does not exercise sandbox initialization.

## Qualify shared admission and stopped restoration

For a local multi-process app, distinguish the shared admission ledger from each origin's runtime history. Run two actual processes with independent stores against the same ledger, synchronize last-slot requests, and inspect real child events and reservations. Test zero, missing and exhausted allowances, immutable replay and conflicts. A foreign process may read a shared committed receipt while lacking the original history; pending reconciliation must use the recorded origin and original handles, without refund or redispatch.

Use the optional repository example's saved `examples/eve-local/PLAYBOOK.md` and `scripts/run-local-recovery.py` for the pinned synthetic qualification. Inspect its interface first: it needs an installed pinned dependency directory, a new private work directory, two available loopback ports, values and an independently chosen expected total. A port permission failure is distinct from an occupied port; use the host's normal authorized execution boundary. Do not evade it or infer process isolation from that approval.

For stopped recovery, stop and verify all writers before copying a complete consistent bundle: source/pins, each origin's workflow state and snapshots/dev metadata, the shared ledger and journal family, origin map and witness. Validate inventory, hashes and required files before restoring fresh directories at the original paths; then start distinct processes and read the original completed and pending handles. The example's `--verify-bundle PATH` is read-only and rejects missing or altered state and mixed execution arguments. It checks consistency, not authenticity against an attacker able to rewrite both files and hashes. Keep runtime data and traces private. Copying only SQLite does not restore separate local-world histories.

The 0.4.2 procedure qualifies same-path, same-version, quiescent local restoration. It does not establish live backup, relocation, cross-host replication, migration, at-most-once external effects or hostile-process isolation. Freeze those target-specific gates separately before relying on them.
