# Representative examples

These are authored illustrations of the contract, **not executed evidence**. Actual build validation is in [the report](../validation/REPORT.md).

## Existing report template

User: “Build my weekly operations report agent from this template. Manual runs only for now.” Inspect the existing project/index and actual template. Establish source rows, required headings, audience, freshness, exact calculations and output destination. For rows 20 and 22, define Total=42 from the source before executing. Use the template; index the individual report as a separate output. Record source/check/output evidence. Leave registration unregistered; “weekly” describes the task and does not request a schedule.

If the user later requests Monday 09:00 execution, settle timezone, dependency/order, overlap, attempts/stops and notification intent, inspect existing jobs and register only through a supported authorized integration. Verify its actual ID/status. One manual run does not prove recurrence.

## Ambiguous document judgment

User: “Build an agent that flags important complaints.” A delayed delivery and confusing invoice do not establish importance. Ask the single consequential decision: what rule should distinguish an important complaint, using those two examples? Teach back the chosen rule, work the examples, and define observable acceptance/escalation for a borderline case. Until settled, deliver a draft with the unresolved judgment; do not silently invent priority labels or claim readiness.

## Independent research

Two source reviews can benefit from bounded children. Give each its source set, citations/output contract, tools, permitted local file, owner, authority and checks. With depth 1, concurrency 2 and two total workers, the children cannot spawn grandchildren or write each other's artifacts. Their work plus parent integration/review uses the shared time/attempt budget. Parent checks coverage, conflicting evidence and source support. If concurrency/depth/workers is zero, run serially without children or prepare handoffs; never replace zero with a default. A task contract is not proof a child was launched.

## Failed quality check

Frozen check: the reported total must equal the input-row sum. Actual output 41 versus input 20+22 fails. Preserve the criterion, correct to42, rerun the same check and a zero-containing regression (0+5=5). Record cause and correction, e.g. a stale hard-coded total, and update the procedure/template only when the failure demonstrates that reusable problem. Record versions and evidence. After the allowed attempts, stop with a partial/failure report rather than weakening exact equality to “approximately correct.”

## Repeated request and missing inventory

“Run that report agent again” means find and read its existing playbook/toolbox/history. Inspect the fitting template and reuse it. A new `outputs/report-02.md` needs its own index entry. A script marked validated with missing evidence loses its supported validation claim until evidence is recovered or its check reruns. Repeated requests do not justify duplicate projects. Private `.private/` interview records stay out of skill exports. Structural completeness still cannot establish content correctness.

## Scheduler unavailable or previous send uncertain

Without scheduler access, deliver the complete requested trigger/timezone/overlap/dependency/retry/stop/notification configuration, state **unregistered**, and name the missing registration/readback capability. Inspect the existing queue reference; do not create a parallel queue.

If a prior send has no provider response, its outcome is uncertain. Inspect available provider records and idempotency/run key before retrying. Without lookup access, retain the prepared output and stop the send; name the exact lookup/reconciliation needed. Absence of recorded success is not evidence of failure. Saved authority from a prior job does not authorize a new action.

## Activation boundary

“Build an agent for invoice review” activates the builder. “Review this invoice” and “Summarize this article about agents” are ordinary task requests. An existing Agent Forge project's explicit repair/extension request activates the skill without restarting settled interviews.
